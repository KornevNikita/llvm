This extension is written against the SYCL 2020 revision 11 specification.  All
references below to the "core SYCL specification" or to section numbers in the

C++ standard library.

== Overview

This extension adds a set of built-in functions that perform a 4-element integer
dot product of two vectors and accumulate the result with a third operand.
These functions may map to specialized hardware instructions when available.
When such instructions are not available, the implementation may emulate the
operation in software.

The primary use case is for kernels that frequently compute small dot-products
(e.g. for certain matrix / tensor operations or DSP-style computations) and want
a compact, efficient idiom.

=== Dot product accumulate functions

This extension adds the following free functions in the namespace
`sycl::ext::oneapi`.

These functions are available both on the host and on the device.

==== Vector overloads

[source,c++]
----
namespace sycl {
namespace ext {
namespace oneapi {

int32_t dot_acc(vec<int8_t,  4> a, vec<int8_t,  4> b, int32_t c);
int32_t dot_acc(vec<int8_t,  4> a, vec<uint8_t, 4> b, int32_t c);
int32_t dot_acc(vec<uint8_t, 4> a, vec<int8_t,  4> b, int32_t c);
int32_t dot_acc(vec<uint8_t, 4> a, vec<uint8_t, 4> b, int32_t c);

} // namespace oneapi
} // namespace ext
} // namespace sycl
----

*Semantics:*

For all overloads above, the function computes:

* `result = dot(a, b) + c`

where `dot(a, b)` is the mathematical dot product of the four vector elements:

* `dot(a, b) = a[0]*b[0] + a[1]*b[1] + a[2]*b[2] + a[3]*b[3]`

The multiplication and addition are performed as integer arithmetic.  The
implementation uses an intermediate type sufficient to preserve the exact
mathematical result for the supported input element widths, and the final
result is returned as `int32_t`.

*Notes:*

* For the overloads involving `uint8_t`, the corresponding operand elements are
  treated as unsigned values during multiplication.
* The functions are intended to allow mapping to hardware dot-product
  accumulate instructions when available.

==== Scalar overloads

Some implementations also provide scalar forms that operate on packed values.
When supported, the following overloads are available:

[source,c++]
----
namespace sycl {
namespace ext {
namespace oneapi {

int32_t dot_acc(int32_t  a, int32_t  b, int32_t c);
int32_t dot_acc(int32_t  a, uint32_t b, int32_t c);
int32_t dot_acc(uint32_t a, int32_t  b, int32_t c);
int32_t dot_acc(uint32_t a, uint32_t b, int32_t c);

} // namespace oneapi
} // namespace ext
} // namespace sycl
----

*Semantics:*

These overloads conceptually interpret `a` and `b` as a packing of four 8-bit
elements and compute the same operation as the vector overloads, i.e.
`dot(a, b) + c`.

The mapping from the 32-bit integer inputs to the 4 packed 8-bit elements is
implementation-defined.  These overloads are provided for compatibility with
targets where packed dot-product instructions naturally accept 32-bit operands.

== Implementation notes

This non-normative section provides information about one possible
implementation of this extension.  It is not part of the specification of the
extension's API.

An implementation may lower `dot_acc` to a target-specific dot-product
accumulate instruction if available.  Otherwise, it may implement `dot_acc`
using ordinary integer multiplication and addition.
